## Summary

- **Authoritative runtime catalog:** `assets/data/gearCatalog.json` (41 records). It is the only
  file the Stocking Advisor (and the gear page's filter-id lookup) loads at runtime.
- **The earlier reports quoted the wrong file.** The tank ranges in the merged threshold report's
  Appendix A (AquaClear 70 "19–49", Fluval 307 "19–50", EHEIM 2213 "7–19") come from
  `assets/data/gear/filters.json`, which **no runtime code loads**. The live values are different
  (AquaClear 70 **40–75**, Fluval 307 **40–75**, EHEIM 2213 **0–20**) — and are still wrong.
- **Every live `minGallons`/`maxGallons` is derived from GPH by a fixed bucket function** (41/41
  records reproduce exactly) from a script that was deleted in October 2025. None is a
  manufacturer rating.
- **37 of 41 records have a tank range that disagrees with the manufacturer's rating**, 2 have no
  manufacturer rating to compare, and 2 match only by coincidence of the bucket edge.
- **Bad ranges do not affect filtration scoring.** They decide which products appear in the
  Filter Product dropdown for the selected tank and are printed in the option label.
  **GPH is the only catalog field that reaches scoring.**
- **9 records have unsupported GPH** (7 sponges, 1 undergravel, 1 unidentified hygger), plus 1
  record whose GPH contradicts the manufacturer (Tetra Whisper IQ 45: 260 vs 215).
- **9 surplus duplicate records** in 8 duplicate groups (41 records = 32 distinct products).
- **0 circulation-only devices** in the catalog.
- **Not yet safe** to build the filtration-status UI on top of (section 13).

## 3. Tank-range derivation

**Exact generation logic.** The live ranges were produced by `inferRangeFromGph` in
`scripts/make-filter-catalog.mjs` (added in #1046, commit `d84030ac`; file deleted in #1091),
used whenever a source record had no range — which was every record:

```js
function inferRangeFromGph(gph) {
  if (gph <= 120) return { min: 0,  max: 20 };
  if (gph <= 220) return { min: 20, max: 40 };
  if (gph <= 400) return { min: 40, max: 75 };
  if (gph <= 650) return { min: 55, max: 125 };
  return            { min: 75, max: 210 };
}
```

Re-running this function over the stored `gphRated` reproduces **41 / 41** stored ranges exactly.
Every live range is therefore **D (derived)**: a GPH bucket, not a manufacturer rating, and not a
turnover rule either (the buckets imply ~3×–6× GPH ÷ max gallons, inconsistently).

Consequences of bucketing by GPH:

- Products are rated for tanks far outside their bucket (EHEIM 2213: rated to 66 gal, bucket 0–20;
  Cascade 1500: rated to 200 gal, bucket 40–75).
- Product names contradict their own ranges: "AC30 … 10–30 US Gal" stored 20–40; "Fluval C2 … up
  to 30 Gal" stored 0–20; "AQUANEAT … Large up to 60Gal" stored 20–40; "Aqueon QuietFlow 75 … Up
  To 90 Gallon" stored 40–75; "Powkoo Dual Sponge Filter (20–55G)" stored 20–40; "Penn-Plax
  Undergravel … 20 (Long) – 29 Gallon" stored 20–40.
- Sponge ranges inherit the invented sponge GPH (section 6), so they are derived from an
  unsupported number.

The legacy `assets/data/gear/filters.json` uses a *different* derivation
(`floor(GPH×0.65/10)`–`ceil(GPH×0.65/4)`, `scripts/extract-gear-filters.mjs`
`computeGallonsRange`), which is where "19–49" (AquaClear 70) came from. It is not loaded.

- **No sponge manufacturer in the catalog publishes a water-flow GPH.** All are air-driven and
  rated by tank size only (same pattern as Hikari and Aquarium Co-Op in the threshold research).
- The stored GPH values have **no source**: the affiliate CSVs carry no GPH, and the values first
  appear as a hard-coded `RATED_GPH_OVERRIDES` table in `tools/build_filter_catalog.py` (#1034).
- They look like tank-size marketing converted to flow (e.g. "up to 10 gal" → 60, "up to 20 gal"
  → 120, "up to 60 gal" → 200), not measured water flow and not air-pump output (none of these
  products ships with an air pump, and air-pump output is in L/min of air).
- None is VERIFIED; none is reproducibly DERIVED from a stated rule; all 8 are **UNSUPPORTED**.
  NOT APPLICABLE would be the correct classification for a sponge's GPH under a future schema.
- These invented values **are** logic-affecting: they are the GPH used for turnover and the
  "too low" check when a user adds a catalog sponge, and they also drive the sponge's derived
  range (hiding the 40–60-gal AQUANEAT Large from 55-gal tanks).

## 12. Proposed future schema (evaluation only — not created)

Minimal additions per record:

```jsonc
{
  "id": "fluval-307",                 // unchanged; stable key
  "brand": "Fluval", "model": "307",  // model separated from listing title
  "role": "biological",               // "biological" | "circulation"
  "type": "CANISTER",                 // CANISTER | HOB | INTERNAL | SPONGE | UGF | SUMP | POWERHEAD
  "tankRating": { "minGal": 40, "maxGal": 70, "source": "<url>", "grade": "A" },  // null for circulation
  "flow": [
    { "gph": 303, "kind": "pump_output",       "source": "<url>", "grade": "A" },
    { "gph": 206, "kind": "filter_circulation", "source": "<url>", "grade": "A" }
  ],                                   // kind: pump_output | maximum_flow | filter_circulation | measured | unknown
                                       // sponges / air-driven UGF: flow = [] (not applicable)
  "aliases": ["fluval-307-x"],         // former duplicate ids that resolve here
  "status": "current"                  // current | discontinued | unverified
}
```

Why this is enough:

- **Manufacturer tank rating** is separate from flow and carries its own source and grade — the
  dropdown filter would use it instead of a GPH bucket.
- **Pump output / maximum flow / filter circulation / measured / unknown** are distinguished by
  `flow[].kind`, so the scorer can choose (and label) a consistent basis.
- **Circulation-only equipment**: `role: "circulation"`, no `tankRating`, never scored.
- **Sponge filters**: `type: "SPONGE"`, empty `flow`, `tankRating` only — matching how makers rate
  them and the threshold report's recommendation that sponges not be scored by GPH.
- `aliases` lets duplicates be merged without breaking saved filters or gear-page links.
- Backwards compatibility: a loader can still expose `gphRated` (first `pump_output` or
  `maximum_flow`) and `minGallons`/`maxGallons` (from `tankRating`) while the controller migrates.
